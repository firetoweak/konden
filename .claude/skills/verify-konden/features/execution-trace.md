# 执行轨迹

需求依据见 [Web 执行轨迹](../../../../docs/架构/入口/Web.md#执行轨迹) 和 [SubAgent](../../../../docs/架构/运行/SubAgent.md)。

在通过 Doctor 的隔离实例打开一位已有历史的原生 Bot，点击「执行轨迹」。观察这条路径无需配置模型。用已有长会话核对规模，包含图文输入、整理与委派的场景分别需要相应记录。

- 总轴显示输入、模型、工具、Compact 和 Subagent。「执行记录」按时间混排用户、助手和工具，在列表底部仍能看到总轴。拖动或按方向键操作 `调整执行记录和详情宽度`，两栏各自滚动。
- 放大总轴，框选并调整端点。检索一个已知日期后，轴和记录都落在选择范围内。用「失败」和「按工具筛选」核对展示范围和耗时。
- 从输入节点展开系统提示、历史消息和输入图像。记录顺序和角色与当次请求一致。模型节点的缓存命中、未命中与写入对照已记录 token 数。明确零命中为橙色，缺少命中统计为灰色，旧记录中来源不明的零值按未知查看。工具节点默认打开「参数」，「结果」反映已提交结果，缺结果保持未知。
- 打开「工具目录详情」、Compact 摘要与子轨迹。子轨迹有自己的执行记录，通过「返回上级轨迹」回到父会话。

用 `GET /api/sessions/<id>/trace` 核对记录数与节点时序。按所选 `entry` 检查 `GET /api/sessions/<id>/trace/detail`，子轨迹请求带父会话的 `branch`。证据保存在本地，避免转发真实会话内容。
