# 私聊消息与文件交付

长期 Bot 给用户的私信、同事之间的私信和群发言均显式发送。发给 user 的正文实时显示并保留在历史中。普通工作正文可以结束本轮，不产生私聊气泡或未读。

需求依据：[交互与响应：长期 Bot 显式投递消息](../../../../docs/架构/多智能体/交互与响应.md#长期-bot-显式投递消息)、[附件原件与引用](../../../../docs/架构/上下文/多模态附件.md#原件与引用)。回复与真实执行分开，成果交付保存副本，协作保留来源和隐私范围。

## Sub-features

- `reply`　显式给 user 的消息按顺序展示，可以引用与复制，附件随对应消息提供下载。
- `live`　显式发送后正文立即可见，刷新后保留原消息。普通工作正文不生成预览或气泡。工具明细和思考各自折叠，由用户展开。
- `unread`：离开当前 Agent 后，它的新回复计入未读，并在名册条目右侧显示红色数字，超过 99 显示 `99+`；进入对应会话后清除。
- `explicit-peers`：普通结尾不会自动成为同事私信或群发言。
- `file`：`send_file` 带工作区相对路径，正文说明可省略，交付文件副本；PNG、JPEG、WebP、GIF 直接显示图片，点击放大后可下载原图，正文不固定附加文件名或大小。其他文件保留下载卡片。
- `mixed-images`：Markdown 正文保留“前文—图片—后文”的输出顺序，图片替代文字用于可访问名称，不自动显示为图注。图片可放大并下载，送达与刷新历史后仍保留顺序。

## How to get to it (user POV)

无需项目，创建两个 Agent，例如 Ada 与 Lin。打开 Ada 的会话先发送普通提问，再让 Lin 用 `send_message` 找 Ada 处理事项。例行任务入口见 routines，群消息入口见 group-chat。

## Driving it with the browser

- **直接回答**：发 `请只回复 PING_OK`，确认实际发给 user 的私信出现；右键回复正文后选择 `复制消息`，刷新后正文相同。
- **执行过程**　发出私聊后继续调用工具，再发最终结果。每条显式私聊只展示一次，普通工具前言和结尾不进私聊。检查展开选择和刷新后的引用、复制。
- **协作触发**　让 Lin 私信 Ada，在同事私信中完成答复。在群里发一条通知再点名提问，核对照常处理问题，知悉类通知无需回帖，用户私聊没有自动转发。
- **实时与未读**　停在 Lin 页面时，Ada 显式发送的私聊增加名册未读数，进入 Ada 后清除；刷新后全文仍可见。
- **文件**：请 Ada 用 `send_file` 分别交付 PNG 和 `note.txt`，其中 PNG 省略 `text`。PNG 默认只显示画面，不能强加说明、文件名和大小栏；点击打开大图预览，在「下载原图」下载。普通文件仍显示名称和大小。核对两种下载原字节、可选正文和刷新后的图片；越出工作区或文件不存在时不出现成功的下载消息。
- **图文混排**：复用本会话已交付图片的 URL，要求 Bot 给 user 发一段前文、一张 Markdown 图片、一段后文，不再生成图片。实际观察收到的私聊，核对文字和图片的顺序、图片解码、可打开预览与下载。检查 1440px、390px 明暗主题与刷新历史，不能把单独的附件交付当作已验证正文图文混排。
- **隔离**：普通会话继续向用户回复；SubAgent 普通文字送给父 Agent，不直接送给用户，也不结束协作。

- **交付副本与协作范围**：交付文本和图片后记录下载哈希，再修改文本源文件、删除源图片；刷新及重启后原附件字节、名称与说明保持，引用仍按本会话隔离。群内分派与结论优先留在原群，实际显式发送，不披露无关私聊；与 [group-chat](group-chat.md) 合并验证，普通回复不自动成为协作发送。
