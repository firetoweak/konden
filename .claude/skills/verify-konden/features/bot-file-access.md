# Bot 文件访问范围

来源：`FileAccessFields.tsx`、`FileAccessPanel.tsx`、`assistant/host/file_access.py` 与 `GET/PUT /api/agents/{id}/file-access`。

## Sub-features

- 创建 Bot 时可选 `指定目录` 或 `完全访问`，初始配置在首次运行前保存。指定目录允许多个本机绝对路径，不要求是 Git 仓库；空列表只保留个人目录。
- Bot 资料的 `详情` 中编辑范围，点 `保存访问范围` 才生效；保存失败保留草稿与错误。选择完全访问隐藏目录列表，切回指定目录保留尚未提交的目录草稿。
- 文件工具、命令启动目录与子任务共用该 Bot 的配置。完全访问覆盖当前系统账户可访问的位置，不提供提权或进程隔离，同事目录与材料仍只读。
- 有当前任务、未回收子任务或运行中后台命令时不能修改。保存成功后下一次任务使用新范围，重启保留配置。

## Drive

1. 按 `../SKILL.md` 启动隔离实例并通过 Doctor。准备个人目录之外的临时目录，跨盘场景在另一磁盘准备测试目录。
2. `新建 Bot` 填写 `名字`，在指定目录模式点 `添加目录`，填写 `访问目录 1`，点 `创建`。对照 `GET /api/agents/<id>/file-access`。
3. 从聊天请求在该目录写测试文件，并将它作为 `execute_command` 的 `cwd`。核对真实文件和执行结果，命令应返回该目录。
4. 启动一个可停止的后台命令。资料页移除外部目录并保存，应显示 `请先停止后台命令，再修改文件访问范围。`，草稿不恢复成旧值。
5. 点 `停止命令`，回合空闲后再次保存，应显示 `已保存`。再请求写外部文件和使用外部 `cwd`，两者均应拒绝，原始文件保持不变。
6. 检查 `完全访问` 的选择与说明。只有获准测试整机访问时才在 Web 保存；自动化进程用例也独立验证该模式与权限收窄。
7. 1100 宽度点击 `显示 Bot 资料`，在资料抽屉检查相同表单；保存后刷新，并重启自己启动的实例，确认当前范围保持。

## Evidence

保存创建、冲突、收窄和窄屏的快照与截图；HTTP 证据为上述设置接口及 `GET /api/sessions/<id>`，文件证据为临时测试目录。所有材料仅写本轮证据目录。

## Gotchas

- 目录在后端所在电脑选择，命令的实际文件访问不受这些入口检查隔离。
- 2026-11-02 Windows 隔离 Web + 本机受控模型：创建时指定 E 盘目录、文件写入与命令 cwd、后台命令保存冲突、停止后收窄与拒绝、1100 宽度资料抽屉通过。完全访问的整机执行与收窄由自动化进程用例覆盖；Web 仅检查选项展示。原生目录选择窗口、真实模型的自主选择未验证。
