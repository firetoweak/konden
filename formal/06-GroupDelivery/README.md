# 群聊投递、回应消费与接管

## 实现与范围

`Send` 在一条群事实里确定发言身份、消费的回应关系、讨论深度和下一批收件人。成员副本和回应请求可晚到。Host 丢失队列后，`Recover` 从群端保留的发言与派单记录恢复；人的新发言替换仍待推进的安排。对应 [AgentGroups 的发送、落账与恢复](../../konden/assistant/host/agent_groups.py) 和 [发送身份与源头计数](../../konden/assistant/host/agent_messages.py)。

配置包含两个成员、一个活动讨论、一条替换讨论的人的插话，以及 Host 或成员合计最多两次崩溃。三个候选发送身份竞争同一源头的两个名额，轮数上限为二，每次检查的回复上限可为一或二。模型把每次派单登记与成员实际收到请求分开，保留已收到的请求。为控制状态空间，同一发言只有一个下一回应者，正文用身份标记，重试必须匹配原正文。实际多成员批次合并、跨群源头和 IPC 时序需要另验。

## 检查的性质

`AtMostOnceConsume` 核对两次发言使用的回应关系互不重叠，`IdempotentSend` 核对一条发送身份只产生一条发言，`BudgetNeverExceeded` 分别检查轮数、回复量和源头量。`RecoveryFromGroupLog` 对照权威安排与重建队列，`InterjectionDoesNotRevoke` 检查每次转换后成员已经收到的消息和请求仍然存在。这里检验恢复与重投的安全性，成员可以不回应。

## 实测与变异复核

在仓库根目录运行 `python scripts/ci.py formal --model 6`。Windows、Temurin 21.0.13+9、tla2tools 1.7.4、单个 TLC worker，生成 465,524 个状态，去重后 50,544 个。已缓存 jar 的整条命令用时 3.76 秒。

在模型临时副本中，删除 `Send` 的 `id \notin Ids` 条件，允许重试重新进入新发言提交。用同一条命令运行，TLC 报告 `IdempotentSend`。先发布一条回应并分发副本，再用同一发送身份提交，最短轨迹共 9 个状态。原模型复核运行通过。

另将 `Recover` 的群端待派范围换为成员副本集合。Host 在首条消息送达成员前崩溃，恢复后遗漏回应安排，`RecoveryFromGroupLog` 在第 3 个状态报错。

## 日落条件

如果群不再维护回应关系和额度，或权威群事务及成员投递已由同一个更低层协议模型覆盖，删除本模型。
