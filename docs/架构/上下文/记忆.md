# 记忆

记忆承载短小、常用的长期工作约束，包括用户对某类工作的明确长期要求。当前任务用[工作计划](工作计划.md)，经历查[历史](上下文压缩.md#历史回查)，完整知识和方法归档后按需读取。

## 适用范围与维护

共同记忆面向团队，个人记忆跟随 Bot 长期身份，不随项目、改名或压缩改变。个人约束只补充共同约束，例外须有用户依据。人可编辑两者；Bot 可维护共同正文和自己的个人正文。当前用户要求优先，记忆不扩大权限，也不替代身份和历史。

正文可为空，在较小硬上限内整体修订，超限拒绝而不截断。容量用于取舍，无须填满；过时删除、重复合并、明确纠正替换旧要求，临时要求不持久化。是否值得记住由人或模型判断。共同记忆须有明确的团队适用依据，不能把针对某位 Bot 的要求默认扩大给所有成员。

## 主动检查

每位长期 Bot 累积五条新增的人或协作消息后，在前台处理停稳且没有待执行命令和控制审批时，安排一次独立的记忆检查。检查沿用该 Bot 当前模型，只能修改现有共同和个人记忆，每种最多一次；不继续原任务，也不生成 Skill 或其他知识结构。子 Agent 与压缩阅读过程不参加检查。

检查读取新增消息、相关回复以及两份当前记忆，保留说话者、时间和原始引用。优先处理用户明确的长期要求和纠正，不从助手的总结、同事转述或一次性要求推断用户长期偏好。一次请求最多使用 32,000 字符的对话材料，每条文字最多 4,000 字符；省略和截断明确标记，不把缺失内容当作事实。它不代替完整历史回查，也不读取附件或总结完整工具输出。

前台新工作、停止与关闭会取消未完成检查，已经写入的内容保持有效。写入继续使用现有参数校验、容量上限、已读版本及操作身份，冲突或超限如实记录，不覆盖别人修改，也不在同一次检查中反复整理。

检查的请求、响应和实际工具结果独立留痕，区分已修改、无需修改、失败与取消；过程记录不进入普通对话上下文。成功检查推进已审视位置，失败或取消不推进；下一条新增消息到来后才有下一次尝试。首次启用从最近已经处理的历史位置开始，不追溯整理整段 Bot 生涯。进程退出后未完成的检查保持未确认，不承诺补做每段历史。记忆写入后的生效仍沿用下述观察机制。

## 共同编辑与来源

修改基于已读版本；版本冲突返回最新正文，核对后再改，不能覆盖未读内容。Web 保留当前页面内未保存草稿并展示新版本，关闭或切换设置不丢草稿，切换 Bot 不串用个人草稿。

正文与修订来源一起保存，同一操作重试不重复修改。Bot 修改可回查执行记录，人的直接修改标明用户来源。

每次判断前读当前记忆，首次或变化后先提交完整原文，未变化不重复。工具写入成功也不替代这次读取。上下文只用已提交观察，变化与清空按序追加；旧版留在原处，失去当前效力，不回填历史开头。是否实际用于判断以冻结请求为准。

## 压缩与恢复

新窗口原文重述冻结点最近观察，期间更新按原顺序保留；摘要不复制或概括记忆正文，新判断仍读取尚未观察的变化。重述和重放不反写当前记忆。同窗只追加变化，切窗建立新前缀，不承诺跨窗口缓存命中。
